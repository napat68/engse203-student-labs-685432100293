# DATABASE_CHOICES — ENGSE203 LAB 11

## 1. ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB

โปรเจกต์ Campus Service เลือกใช้ SQLite เพราะข้อมูลในระบบมีโครงสร้างชัดเจน โดยแบ่งเป็นตาราง `users` และ `requests` ซึ่งมีความสัมพันธ์กันผ่าน `requester_id` ที่เป็น Foreign Key จึงเหมาะกับฐานข้อมูลเชิงสัมพันธ์ นอกจากนี้ SQLite ยังใช้งานง่าย ไม่จำเป็นต้องติดตั้ง Database Server แยกต่างหาก ทำให้สะดวกต่อการพัฒนาและทดสอบในเครื่อง ส่วน MongoDB เป็นฐานข้อมูล NoSQL ที่เหมาะกับข้อมูลแบบ Document ซึ่งสามารถมีโครงสร้างที่ยืดหยุ่นได้มากกว่า แต่ระบบนี้ยังไม่มีความจำเป็นต้องใช้ความยืดหยุ่นดังกล่าว

## 2. ถ้าวันหนึ่งต้องเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง

หากเปลี่ยนจาก SQLite ไปใช้ MongoDB จะต้องแก้ไขชั้น Service เพราะรูปแบบการเชื่อมต่อฐานข้อมูลและคำสั่ง Query เปลี่ยนจาก SQL ไปเป็นการจัดการ Document นอกจากนี้ยังอาจกระทบชั้น Controller เนื่องจาก MongoDB Driver ทำงานแบบ async และคืนค่าเป็น Promise จึงต้องใช้ `async/await` เพื่อรอผลลัพธ์จากฐานข้อมูล ส่วน Route และ Frontend สามารถคงรูปแบบเดิมได้ หากยังรักษา API Contract และรูปแบบ JSON ที่ส่งกลับให้เหมือนเดิม การแยกชั้นระบบจึงช่วยลดผลกระทบจากการเปลี่ยนเทคโนโลยีฐานข้อมูล

## 3. async จำเป็นเมื่อไร และไม่จำเป็นเมื่อไร

การใช้ async จำเป็นเมื่อโปรแกรมต้องรอการทำงานที่ไม่เสร็จทันที เช่น การเรียก API ผ่านเครือข่าย หรือการเชื่อมต่อฐานข้อมูล MongoDB ที่ทำงานแบบ asynchronous โดยใช้ `await` รอผลลัพธ์โดยไม่บล็อก Event Loop ระหว่างนั้น สำหรับโปรเจกต์นี้ใช้ SQLite ผ่าน `node:sqlite` แบบ `DatabaseSync` ซึ่งเรียกใช้คำสั่งฐานข้อมูลแบบ synchronous จึงไม่จำเป็นต้องใช้ async/await ใน Service ที่อ่านหรือเขียนข้อมูล อย่างไรก็ตาม หากในอนาคตเปลี่ยนไปใช้ฐานข้อมูลระยะไกลหรือ Driver แบบ asynchronous ก็ต้องปรับ Service และส่วนที่เรียกใช้งานให้รองรับ Promise อย่างถูกต้อง
