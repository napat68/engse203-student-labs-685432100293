| คอลัมน์ | ใส่อะไร | ตัวอย่างสิ่งที่เขียน **(บั๊กสมมติ)** |

| **ไฟล์ : บรรทัด** | ไฟล์ที่แก้ + เลขบรรทัด | `Foo.jsx : 12` |
| **สาเหตุ** | **ทำไม** มันทำงานผิด (ไม่ใช่แค่ "พิมพ์ผิด") | "ใส่วงเล็บท้ายชื่อฟังก์ชัน เลยถูกเรียกทันทีตอน render" |

## บันทึกของฉัน — กรอกทั้ง 6 บั๊ก

| # | อาการ (ให้มาแล้ว) | ไฟล์ : บรรทัด | สาเหตุ (ทำไมผิด) | แก้อย่างไร |
|---|---|---|---|---|
| 1 | Console เตือนสีเหลืองเรื่องรายการ (list) | `RequestList.jsx : 16` | ใน `RequestList` มีการใช้ `.map()` เพื่อสร้าง `RequestCard` หลายรายการ แต่แต่ละ component ไม่ได้กำหนด `key` ที่ไม่ซ้ำกัน ทำให้ React ไม่สามารถติดตามได้ชัดเจนว่า element ใดใน list เป็นรายการไหน เมื่อมีการเพิ่ม ลบ หรืออัปเดตรายการจึงเกิด warning ใน Console | เพิ่ม `key={request.id}` ให้กับ `RequestCard` ที่อยู่ภายใน `.map()` โดยใช้ `request.id` เพราะเป็นค่าที่ไม่ซ้ำของแต่ละคำร้อง ทำให้ React สามารถระบุและจัดการแต่ละรายการได้ถูกต้อง |
| 2 | ตัวเลข "รอดำเนินการ" ในแผงสรุปไม่ตรงกับที่เห็นจริง | `DashboardPage.jsx : 48` | ตัวแปร `pending` ใน summary เดิมใช้เงื่อนไขตรวจ `request.status === 'completed'` จึงไปนับจำนวนรายการที่เสร็จแล้วแทนที่จะนับรายการรอดำเนินการ ทำให้ตัวเลขในช่อง pending ไม่ตรงกับข้อมูลจริง | เปลี่ยนเงื่อนไขของ `pending` จาก `request.status === 'completed'` เป็น `request.status === 'pending'` เพื่อให้นับเฉพาะรายการที่มีสถานะรอดำเนินการจริง แล้วตรวจว่าค่ากลับเป็น 3 รายการตามข้อมูลเริ่มต้น |
| 3 | กดตัวกรอง "รอดำเนินการ" แล้วได้รายการที่ไม่ใช่ | `DashboardPage.jsx : 56-57` | เงื่อนไขเดิมใช้ `request.status !== statusFilter` ซึ่งหมายถึงเก็บรายการที่สถานะ "ไม่เท่ากับ" ค่าที่ผู้ใช้เลือก ดังนั้นเมื่อเลือก pending จึงได้รายการสถานะอื่นแทน | เปลี่ยนจาก `!==` เป็น `===` ให้รายการผ่าน filter เมื่อ `request.status` ตรงกับ `statusFilter` และยังคงกรณี `statusFilter === 'all'` เพื่อให้เลือกดูทั้งหมดได้ตามเดิม |
| 4 | เปลี่ยน URL `REQ-001` → `REQ-002` แล้วข้อมูลไม่เปลี่ยน | `RequestDetailPage.jsx : 28` | `useEffect` ที่ใช้โหลดรายละเอียดคำร้องเดิมไม่ได้ใส่ `requestId` ไว้ใน dependency array เมื่อ URL เปลี่ยนจากคำร้องหนึ่งไปอีกคำร้องหนึ่ง แต่ component ยังเป็นตัวเดิม React จึงไม่เรียก effect ใหม่ และหน้าจอยังคงแสดงข้อมูลของ request เดิม | เพิ่ม `requestId` เข้าไปใน dependency array เป็น `[requestId, reloadKey]` เพื่อให้ effect ทำงานใหม่ทุกครั้งที่ `requestId` ใน URL เปลี่ยน จากนั้นทดสอบเปลี่ยน REQ-001 เป็น REQ-002 แล้วรายละเอียดเปลี่ยนตามทันที |
| 5 | กด "ลบ" แล้วรายการยังอยู่ ต้องรีเฟรชถึงหาย | `DashboardPage.jsx : 74` | `deleteRequest(requestId)` คืนค่า array ชุดใหม่ที่ลบรายการนั้นออกแล้ว แต่โค้ดเดิมไม่ได้ใช้ array ใหม่นั้นมาอัปเดต state ทำให้ `requests` ใน React ยังเป็นข้อมูลชุดเดิม จึงยัง render card ที่ถูกลบอยู่จนกว่าจะโหลดข้อมูลใหม่ | รับค่าที่คืนจาก `deleteRequest()` เก็บไว้ใน `nextRequests` แล้วใช้ `setRequests(nextRequests)` เพื่ออัปเดต state ทันที หลังแก้เมื่อกดลบ card จะหายจากหน้าโดยไม่ต้อง refresh |
| 6 | กด "Reset Demo Data" แล้วหน้าพัง/ว่างเปล่า | `DashboardPage.jsx : 93-94` | `resetRequests()` เป็นฟังก์ชัน async จึงคืนค่าเป็น Promise ก่อนที่จะได้ array ข้อมูลจริง หากนำผลไป `setRequests()` ทันทีโดยไม่ `await` state จะไม่ได้รับ array ของ requests ที่ถูกต้อง ทำให้ขั้นตอน render ผิดพลาดหรือหน้าแสดงข้อมูลไม่ถูกต้อง | เปลี่ยนให้รอผลด้วย `const nextRequests = await resetRequests();` แล้วจึง `setRequests(nextRequests)` ทำให้ state ได้ array หลัง reset เสร็จจริง จากนั้นทดสอบกด Reset แล้วข้อมูลตัวอย่างกลับมา 5 รายการตามเดิม |
